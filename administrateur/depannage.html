    Dépannage¶

    Premiers gestes¶

    docker compose ps                        # qui est debout, qui est unhealthy
docker compose logs --tail=100 backend   # le dernier message utile
nvidia-smi                               # la carte répond
df -h ~ && du -sh ~/.cause/*             # la place
curl -s http://localhost:8090/api/licence

    Symptômes fréquents¶

    Symptôme Cause probable Que faire
    Le navigateur n'ouvre pas l'application, ou boucle vers le nom du site Pas de certificat HTTPS. Suivre HTTPS.
    Le micro est refusé Contexte non sécurisé, donc pas de certificat. Idem.
    Le backend reste unhealthy au démarrage Il attend Whisper et Ollama. Le premier chargement de large-v3 dépasse deux minutes, le téléchargement du modèle Ollama peut prendre une heure. Attendre, suivre docker compose logs -f ollama.
    Journal Ollama failed to pull Nom de modèle inexistant, DNS ou réseau. Vérifier OLLAMA_MODEL dans ~/.cause/.env et la connexion.
    Aucun conteneur ne sort sur Internet, alors que l'hôte y est Le routage IPv4 de l'hôte est coupé. cat /proc/sys/net/ipv4/ip_forward doit valoir 1. sudo sysctl -w net.ipv4.ip_forward=1, puis le rendre durable avec un fichier dans /etc/sysctl.d/.
    Rapport en erreur « Délai dépassé en attente de la transcription des segments » Whisper est saturé ou arrêté. Vérifier Whisper, relancer la génération depuis la consultation.
    Rapport en erreur « Aucune dictée enregistrée » ou « Aucun enregistrement audio » Génération demandée sur une piste sans audio. Le médecin doit d'abord enregistrer.
    Rapport en erreur « La rédaction a été interrompue avant d'aboutir » Le serveur s'est arrêté pendant la rédaction. Rien à réparer : le médecin relance la génération, ses enregistrements sont intacts.
    Un rapport reste indéfiniment « en cours de génération » Une tâche est vivante mais bloquée. Lire les journaux du backend et d'Ollama, puis docker compose restart backend : la rédaction est close en erreur et relançable.
    Disque plein, ou avertissement « Le dossier audio occupe N Go » Les audios ne sont plus purgés. Archiver ou supprimer les plus anciens fichiers de ~/.cause/audio/, qui ne sont plus nécessaires au fonctionnement. Voir Purges automatiques.
    « Cette consultation est en cours d'enregistrement par un autre médecin » Verrou de visibilité, trente minutes après la dernière activité. Attendre l'expiration, ou faire terminer l'enregistrement par son initiateur.
    « Accès refusé : rôle ... non autorisé » Fonction d'administration appelée par un compte non ADMIN. Utiliser un compte ADMIN.
    Une consultation, un patient ou un compte a disparu après une restauration Son fichier est vide, tronqué ou sans identifiant. Le serveur l'ignore. docker compose logs backend \| grep 'ignoré au démarrage' nomme le fichier fautif. Le restaurer depuis une sauvegarde.
    Plus aucun type d'acte n'est proposé Le dossier ~/.cause/act-types/ ne contient que des fichiers inexploitables. Vider le dossier et redémarrer le backend : le catalogue livré est réécrit.
    Le mot de passe admin est introuvable dans les journaux Un compte ADMIN existait déjà au démarrage. Réinitialiser depuis un autre compte ADMIN.
    Une mise à jour ne change rien au comportement du serveur Le conteneur tourne encore sur l'ancienne image. La colonne IMAGE de docker compose ps affiche un sha256:... au lieu d'un nom. docker compose up -d <service>, qui recrée le conteneur. restart ne suffit que pour ce qui est lu hors du programme : un fichier de ~/.cause/, un certificat, une variable.
    Aucun manuel dans l'application, et le chatbot ne répond rien L'image du backend a été construite sans les manuels. Le journal porte « Manuel ... absent du jar ». Signaler à l'éditeur : l'image est à reconstruire.
    403 sur les QR codes Droits sur le dossier qrcodes. Relancer le script, puis docker compose restart frontend.
    L'installation signale « manque » ou « taille différente » sur un fichier du disque Copie interrompue, disque débranché, ou fichier modifié depuis la préparation. L'installation continue, c'est à vous de juger. Voir Vérifier un disque sans rien installer.
    L'installation s'arrête au moment de tirer les images, ou docker compose pull répond denied Jeton de lecture absent, expiré ou sans le droit read:packages. Reposer le jeton, voir Le jeton du registre, ou se connecter à la main par sudo docker login ghcr.io.
    Au démarrage, « No such image: cause-whisper:... », cause-ollama ou cause-qwen-asr L'image du moteur n'a pas été chargée depuis le disque, ou la ligne CAUSE_MOTEURS de ~/.cause/.env ne désigne pas celle qui est chargée. docker image ls \| grep cause- pour voir ce qui est là, puis relancer le script du disque.
    Bandeau rouge « Licence refusée, arrêt dans ... » Refus de licence, la fenêtre de soixante-douze heures court encore. Appeler l'éditeur maintenant, avec les trois lignes d'empreinte. Voir La licence machine.
    Écran « Kauze ne peut pas démarrer sur cette machine » Licence absente, modifiée ou émise pour un autre serveur, fenêtre écoulée. Suivre Le logiciel s'est arrêté. Les données ne sont pas touchées.
    Arrêt immédiat, l'écran disant qu'aucune fenêtre n'a été accordée Le compteur ~/.cause/licence-grace.txt est absent ou a été modifié. Voir Le compteur des heures. Ne pas l'écrire à la main.
    Écran « Kauze ne sait pas sur quelle machine il tourne » Montage d'identité manquant dans docker-compose.yml. Défaut d'installation, pas de licence. L'écran nomme chaque source et son chemin. Rétablir les montages, docker compose up -d.
    Bandeau « Licence de maintenance échue » Redevance annuelle arrivée à échéance. Rien n'est bridé. Contacter l'éditeur.
    « Permission denied » en modifiant ~/.cause/.env Installation posée avant la 1.0.15 : les fichiers appartiennent à root. sudo chown $USER:$USER ~/.cause/.env ~/.cause/.env.backend ~/.cause/.env.backend.overrides ~/.cause/docker-compose.yml, une fois pour toutes.
    Un réglage a disparu, l'application est revenue à son comportement par défaut Le réglage était écrit dans ~/.cause/.env.backend, que le script réécrit à chaque passage. Le réécrire dans ~/.cause/.env.backend.overrides, voir Régler l'application.
    setup.sh upgrade annonce une version que vous avez déjà, alors que l'éditeur en a publié une plus récente Le setup.sh en place date d'avant la 1.0.23 et réutilise l'outillage gardé en cache par Docker. sudo docker pull ghcr.io/zero-filtre/cause-outillage:stable, puis relancer la montée. Voir Mettre à jour le logiciel.
    Un réglage écrit dans le fichier de réglages ne fait rien Backend non redémarré, espaces ou guillemets autour de la valeur, ou valeur fixée par le docker-compose. cd ~/.cause && docker compose exec backend printenv <NOM> dit ce que le conteneur voit. Voir Ce que le fichier de réglages ne change pas.

    GPU¶

    Mémo établi sur la machine de référence : RTX 5060 Ti 16 Go, Ubuntu 24.04, noyau HWE. Sans GPU, Whisper ne démarre pas, donc le backend non plus : l'application est indisponible.

    Diagnostic¶

    uname -r
apt-mark showhold
dkms status
modinfo nvidia | grep -E 'version|license'
nvidia-smi
cat /proc/driver/nvidia/version            # version du module chargé
nvidia-smi 2>&1 | grep 'NVML library'      # version des bibliothèques
grep -iE 'nvidia|linux-image' /var/log/dpkg.log | grep -E 'upgrade|install'

    Deux pannes, deux messages.

    Message Cause Remède
    nvidia-smi répond « No devices were found », dmesg porte RmInitAdapter failed Mauvais module : les cartes Blackwell n'acceptent que le module NVIDIA ouvert, modinfo nvidia \| grep license devant répondre Dual MIT/GPL. Ou noyau mis à jour sans son module. Remettre le module en place.
    nvidia-smi répond Failed to initialize NVML: Driver/library version mismatch Les bibliothèques ont avancé sans le module, une mise à jour de sécurité ayant échappé au gel. Les conteneurs déjà debout continuent de tourner, seuls les nouveaux échouent. Redémarrer la machine, puis geler la pile du pilote.

    Remettre le module en place¶

    Ce qu'il faut faire¶

    Trois sorties, dans cet ordre de préférence.

    1. Poser le module précompilé du noyau qui tourne, ce qui ne demande pas de redémarrage :

      sudo apt install linux-modules-nvidia-595-open-$(uname -r)
sudo modprobe nvidia

    2. Revenir au noyau précédent, encore installé, en le choisissant dans le menu avancé de GRUB au démarrage : le GPU revient le temps de réparer.

    3. Revenir à la version précédente d'un paquet du pilote, que le journal dpkg nomme : sudo apt install <paquet>=<version>, l'archive étant encore dans /var/cache/apt/archives.

    Vérifier¶

    nvidia-smi
docker compose up -d && docker compose ps

    nvidia-smi doit nommer la carte et une version de pilote, et les quatre services repasser en healthy.

    Si ça coince¶

    Appelez l'éditeur avec la sortie du bloc de diagnostic ci-dessus.

    Geler la pile du pilote¶

    Obligatoire sur un serveur livré : sans cela, une seule mise à jour du pilote suffit à arrêter la transcription et la rédaction, sans qu'aucun écran de l'application n'en dise la cause. Le gel est posé par le script d'installation, à chaque passage, et remis par le script des mises à jour du système quand il rend la main. Il ne manque que si quelqu'un l'a levé à la main.

    Ce qu'il faut faire¶

    sudo bash ~/.cause/setup.sh

    Le script gèle toute la pile et non ses seuls modules, le noyau compris. Le gel n'est que la seconde ligne de défense : les mises à jour automatiques sont coupées par le même script, voir Mises à jour du système.

    Vérifier¶

    apt-mark showhold

    La liste doit porter les bibliothèques (libnvidia-gl-595, nvidia-compute-utils-595, libnvidia-cfg1-595) et pas seulement les modules, ainsi que linux-image-*, linux-headers-* et linux-modules-*.

    Si ça coince¶

    Appelez l'éditeur.

    Poser le module en DKMS¶

    Solution durable : le paquet nvidia-dkms-595-open recompile le module à chaque changement de noyau. Il exige les en-têtes du noyau HWE et le Secure Boot désactivé.

    Ce qu'il faut faire¶

    L'ordre est impératif.

    1. Retirez les paquets précompilés du pilote.
    2. Installez nvidia-dkms-595-open.
    3. Vérifiez le module avant tout redémarrage.
    4. Gelez les paquets du pilote fermé avec apt-mark hold pour qu'une mise à jour ne les réinstalle pas.

    Vérifier¶

    ls /lib/modules/$(uname -r)/updates/dkms/
dkms status

    Le module doit être listé. Ne redémarrez qu'après cette vérification.

    Si ça coince¶

    Appelez l'éditeur.
