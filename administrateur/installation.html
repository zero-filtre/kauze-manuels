    Installation¶

    Prérequis¶

    Ce qu'il faut Détail
    Ubuntu 24.04 ou plus récent. Aucune autre distribution n'est prise en charge.
    Python 3 Présent d'origine sur Ubuntu.
    GPU NVIDIA Le script s'arrête sans GPU NVIDIA. Configuration de référence : 16 Go de VRAM.
    Espace disque Soixante gigaoctets libres.
    Accès Internet Pendant l'installation, même lent.
    Jeton du registre Voir Le jeton du registre.
    Jeton deSEC Fourni par l'éditeur, voir HTTPS.
    Interface Wi-Fi Optionnel, pour le hotspot. Gardez une autre voie d'accès à la machine.

    Sur une carte de génération Blackwell, RTX 5060 Ti et plus récentes, installez le module NVIDIA ouvert avant de lancer le script : voir Dépannage GPU.

    Installer depuis un disque de livraison¶

    Ce qu'il faut faire¶

    1. Copiez le dossier de livraison du disque vers la machine, pour ne plus dépendre du disque :

      cp -a /media/<vous>/<disque>/livraison-cause-<version> ~/

    2. Placez-vous dedans :

      cd ~/livraison-cause-<version>

    3. Lancez le script :

      sudo bash setup.sh

    4. Rouvrez le terminal, puis déposez la licence reçue de l'éditeur et redémarrez le backend :

      cp <licence reçue> ~/.cause/licence.lic
docker compose restart backend

    5. Vérifiez que les conteneurs tournent.

    Le dossier copié vaut le disque : le script se reconnaît en livraison aux fichiers qui l'accompagnent. Sans licence déposée, le serveur fonctionne soixante-douze heures, voir La licence machine. Le script coupe aussi les mises à jour automatiques du système et gèle la pile du pilote, voir Mises à jour du système.

    Vérifier¶

    docker compose ps

    Les quatre services whisper, ollama, backend et frontend doivent être healthy. Comptez quelques minutes, et jusqu'à une heure si le modèle de langue se télécharge.

    Si ça coince¶

    Dépannage.

    Le jeton du registre¶

    Les images du backend et du frontend sont des paquets privés. Posez le jeton avant la première installation.

    Ce qu'il faut faire¶

    1. Créez sur GitHub un jeton personnel portant le seul droit read:packages.

    2. Écrivez-le sur le serveur :

      umask 077
mkdir -p ~/.cause
echo CAUSE_GHCR_USER=<compte> > ~/.cause/.env.ghcr
echo CAUSE_GHCR_TOKEN=<jeton> >> ~/.cause/.env.ghcr

    3. Quand le jeton expire, remplacez ces deux lignes. L'installation suivante s'y reconnecte seule.

    Vérifier¶

    ls -l ~/.cause/.env.ghcr
docker compose pull

    Le fichier doit être en -rw------- et le tirage ne doit répondre ni denied ni unauthorized.

    Si ça coince¶

    Dépannage.

    Vérifier un disque sans rien installer¶

    Ce qu'il faut faire¶

    cd /media/<vous>/<disque>/livraison-cause-<version>
cat VERSION
while read -r o c; do [ "$(stat -Lc %s "$c")" = "$o" ] || echo "ECART $c"; done < TAILLES.txt

    Vérifier¶

    VERSION nomme la version livrée, le modèle actif, ses replis et les images attendues. La boucle ne doit afficher aucune ligne ECART.

    Si ça coince¶

    Un blob de modèle porte son propre condensé en guise de nom, donc un doute se lève avec le fichier seul :

    sha256sum modeles/ollama/models/blobs/sha256-a8bdd07a...

    Si le condensé calculé n'est pas le nom du fichier, ce blob est abîmé. Voir Dépannage.

    Mettre à jour¶

    Deux mises à jour existent, et elles n'ont rien à voir.

    Ce qui change Il vous faut Compter
    Le logiciel : backend, frontend, scripts, compose Internet Dix minutes
    Les modèles et les moteurs de transcription Un disque de l'éditeur Une heure

    Les modèles pèsent des dizaines de gigaoctets. Ils ne passent pas par Internet, jamais. Tout le reste passe par Internet, et ne demande aucun disque.

    Mettre à jour le logiciel¶

    Sur le serveur lui-même, dans un terminal ouvert avec le compte qui a lancé l'installation, par SSH ou à la console :

    sudo bash ~/.cause/setup.sh upgrade

    C'est tout. Le script va chercher la dernière version publiée par l'éditeur, renouvelle setup.sh, contexte.py, docker-compose.yml et le dossier outils/, inscrit le numéro dans ~/.cause/.env, tire les images du backend et du frontend, redémarre l'application et attend que les quatre services soient sains. Il ne touche ni .env.backend.overrides, ni vos données. Comptez dix minutes.

    Si le script annonce une version que vous avez déjà alors que l'éditeur en a publié une plus récente, votre setup.sh date d'avant la 1.0.23 et réutilise l'outillage gardé en cache. Tirez l'étiquette une fois à la main, puis relancez : le setup.sh neuf le fera seul ensuite.

    sudo docker pull ghcr.io/zero-filtre/cause-outillage:stable
sudo bash ~/.cause/setup.sh upgrade

    Pour viser un numéro précis que l'éditeur vous annonce, par exemple pour revenir en arrière :

    sudo bash ~/.cause/setup.sh upgrade 1.0.20

    Le dossier du disque de livraison n'est plus nécessaire : tout ce qu'il faut pour relancer et mettre à jour vit dans ~/.cause.

    Vérifier¶

    cd ~/.cause
grep ^CAUSE_VERSION= .env
docker compose ps

    La version est celle attendue, la colonne IMAGE du backend et du frontend la porte, et les quatre services sont healthy.

    Mettre à jour les modèles et les moteurs¶

    L'éditeur vous remet un disque. Faites exactement ceci, la machine peut rester en service jusqu'à la troisième commande.

    1. Copiez le dossier du disque sur la machine :

      cp -a /media/<vous>/<disque>/livraison-cause-<version> ~/

    2. Placez-vous dedans :

      cd ~/livraison-cause-<version>

    3. Lancez le script :

      sudo bash setup.sh

    4. Il demande deux clés de sauvegarde. Si vous ne les avez pas, appuyez deux fois sur Entrée : il vous avertit et continue.

    Rien n'est effacé. Patients, consultations, licence, comptes et réglages restent en place. Seuls les fichiers nouveaux ou modifiés sont recopiés, donc ce passage est bien plus court que la première installation.

    Attention, le disque apporte son propre .env et remplace le vôtre. La version, le nom du site et le modèle actif sont donc ceux que l'éditeur a gravés. Annoncez-lui votre nom de site avant la gravure, et contrôlez après coup.

    Vérifier¶

    grep -E 'CAUSE_VERSION|CAUSE_MOTEURS|OLLAMA_MODEL|KAUZE_DOMAINE' ~/.cause/.env
docker compose ps

    Les quatre lignes portent ce que l'éditeur a annoncé, et les quatre services sont healthy.

    Si ça coince¶

    Dépannage.

    Réveiller le second moteur de transcription¶

    Qwen3-ASR est livré sur la machine mais ne démarre pas avec les autres services. Rien n'est à télécharger.

    Ce qu'il faut faire¶

    1. Démarrez le moteur :

      docker compose --profile qwen up -d qwen-asr

    2. Envoyez-lui la dictée, deux lignes dans ~/.cause/.env.backend.overrides :

      ASR_DICTATED_PROVIDER=qwen
ASR_QWEN_URL=http://qwen-asr:8998/v1/audio/transcriptions

    3. Redémarrez le backend :

      cd ~/.cause && docker compose up -d backend

    Pour le rendormir : docker compose stop qwen-asr, et reposez ASR_DICTATED_PROVIDER=whisper.

    Deux réglages du fichier ~/.cause/.env comptent :

    Réglage Effet
    QWEN_MAX_SECONDS Fenêtre audio. Elle décide si le moteur tient dans ce qu'il reste de carte.
    QWEN_DEVICE Carte à utiliser, par exemple cuda:1, plutôt que la première venue.

    Vérifier¶

    docker compose ps qwen-asr
cd ~/.cause && docker compose exec backend printenv ASR_DICTATED_PROVIDER

    Le service doit être healthy et la variable répondre qwen.

    Si ça coince¶

    Dépannage.

    Premier compte administrateur¶

    Ce qu'il faut faire¶

    1. Relevez le mot de passe écrit dans les logs du premier démarrage :

      docker compose logs backend | grep 'Mot de passe'

    2. Connectez-vous avec le compte admin.

    3. Changez ce mot de passe depuis l'onglet Utilisateurs de l'administration.

    Vérifier¶

    Reconnectez-vous avec le nouveau mot de passe.

    Si ça coince¶

    Dépannage.
